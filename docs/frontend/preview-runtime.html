Choosing: which one is "this is the system working"?
  1. T1 (sequential bubbles) — every event becomes a visible widget. The richest audit trail; reviewers can point to a specific agent's bubble for a specific claim. Downside: chat gets long; final report competes with other output.
  2. T2 (merged log) — one timeline, hard to skim. The deliverable becomes one chronological wall. Good for "I want to see everything that happened."
  3. T3 (mini-status + recap) — chat reads like one memo. The recap rail collapses per-agent prose; only the final thesis is fully expanded. Mini-row at top always shows complete progress. This is closest to how Claude Code and Gemini CLI surface multi-agent runs.
  4. Existing code matches T1 best. chat._apply_event already mounts one MessageBubble per agent with streaming deltas. DiffPanel mounts under final-report. Cost widget updates incrementally.
  5. For the Wharton comp where justification matters, T1 is the defensible choice: every claim has an attributable bubble + a citation chip. For a daily-driver tool, T3 is more pleasant.
  6. Recommendation: ship T1 (the existing shape) — it's already wired and the pilot covers it. T2 and T3 are valid follow-ups if chat density becomes a complaint.
