# USER-JOBS — what the project is for

> Every feature in this project maps to one of the five jobs below — or it doesn't ship. If you have to argue why it maps, it's cut.

The Wharton Investment Competition is **the v1 use case**, but not the v1 audience. The audience is anyone who needs a defensible short-form research memo on a public company: Wharton students, retail investors evaluating before talking to their advisor, junior analysts running a first-pass screen, professionals preparing a brief. The shape of the memo doesn't change; the verdict, depth, and emphasis do.

Five jobs rank below in priority order. The rank is the test: a feature moves the closer it gets to job 1; a feature moves down the list the further it gets from job 5. **If a candidate feature moves zero of these, drop it.**

---

## Job 1 — Trust

> *"Can I trust this output? What's the source? Where could it be wrong?"*

This is the only feature a Wharton judge is silently scoring, and the only feature a retail user doubts on every AI-generated report. The user has one lurking question on every output: **is this real or is it machine-made-up?**

**What this means in product terms:**
- Every claim in the final memo has a citation — URL + date + retrieved timestamp.
- Every claim has a confidence label (`HIGH | MODERATE_HIGH | MIXED | LOW`) the system actually earned.
- Contradictions between sources are surfaced, not averaged away.
- The system declares what it cannot answer — abstention is a feature.
- Every run produces a "What could be wrong with this memo" section.

**What the project does today:** Bounds it via the source-verification protocol in `docs/prompts/V2-PROMPT-STANDARD.md` and per-asset gates enforced by `docs/runtime/evals/test_per_asset_coverage.py` + `test_source_verification.py`. **Proven?** Only after the eval suite ships (P0 item 3).

## Job 2 — Action

> *"What do I do with this? Buy, hold, sell? Wait for what?"*

A research memo the user can't act on is a Wikipedia article. The user wants: a directional view, a one-sentence thesis, and the trigger that would change the view.

**What this means in product terms:**
- Every flag-flow memo ends with a 3-line "Bottom line": direction, conviction (1–5), and the price/event that would flip the view.
- Every memo includes the next catalyst date ("next earnings 2026-11-20 — what we're watching").
- The memo includes the bear case in the same flow as the bull — not buried.
- The system never says "I'd need more research" without also saying *which research and where*.

**What the project does today:** Bound by the `conclusion` field and the devil's-advocate specialist in the 5-prompt roster. **Proven?** After P0 item 6 (thesis register) + the f1 acceptance criteria pass.

---

## Job 3 — Speed

> *"How fast can I get a defensible view on a new ticker?"*

This is where AI wins against humans by 10×. The user wants: give me a credible first draft in under 10 minutes.

**What this means in product terms:**
- Single-ticker f1 flow: 5–10 minutes end-to-end on free 70B-class models, <2 minutes on Sonnet.
- Compare-3-tickers flow (f2): under 15 minutes.
- Streaming progress (`activity` field in the orchestrator output) so the user knows the system is alive.

**What the project does today:** Bound by free-model adapter performance + cached tool layer. **Proven?** After P0 items 2 + 5 ship.

---

## Job 4 — Defensibility

> *"When my PM/team/client asks 'why?', can I cite the memo? Does it hold up?"*

This is what makes a Wharton pitch win. It's also what makes a retail user's family trust them.

**What this means in product terms:**
- Every assertion has a primary source URL beside it.
- Every quantitative claim has a date stamp and the figure source (10-Q line, transcript page).
- The memo names its assumptions ("we assumed 22% gross margin continues") so the user knows what to attack.
- A "What an attacker would say" section is mandatory — auto-generated by the devil's-advocate specialist.

**What the project does today:** Bound by forensic-accounting + final-report prompts + the citation-through-flow discipline. **Proven?** After f1 acceptance (P0 item 2).

---

## Job 5 — Comparison

> *"How does ticker A compare to B and C? Which one wins?"*

The second most common real-world analyst job after coverage initiation. Wharton teams do it explicitly (peer comp tables). Junior analysts do it for shortlists. Retail investors do it before buying.

**What this means in product terms:**
- A `f2-compare-tickers` flow that takes 2–5 tickers and produces side-by-side.
- Same metrics, same scoring rubric, same format across all names — comparability is the deliverable.
- The system never says "they're different companies so hard to compare" — that's the human-default cop-out. The system has templates that normalize across sectors.
- Ranking: the system produces a ranked pick, with confidence, not a menu of maybes.

**What the project does today:** Bound by flow f2 (`docs/flows/f2-compare-tickers.md`). **Proven?** After P1 item 7 ships.

## What users do NOT need (the no-build list)

These features sound good, get requested by people who haven't used the product, and **never move the five jobs above.** They are deferred, not deleted, with a reason.

| Feature | Why it's deferred |
|---------|-------------------|
| **A dashboard / charts / visualizations** | Memos > dashboards for trust. Markdown tables are sufficient. A charting library is v3+ if ever — and only if memos lack conviction at scale. |
| **Real-time streaming market data** | Free sources lag; paid sources cost $; the user doesn't need 1-second updates to make a position decision. Daily OHLCV covers 95% of cases. Realtime only if a user pays. |
| **Trading execution / order placement** | Regulatory surface area, not analytical. The user has a broker; we provide analysis, not custody. |
| **Portfolio management UI** | The user already has one. We provide analysis, not custody. |
| **Social sentiment scoring / Reddit scraper** | Sentiment is mostly noise per the social-sentiment literature. The few signals that aren't are already in the price via news. Our sentiment module is skeptical of itself by design. |
| **ESG scoring** | Data is contested (ratings disagree by 30–100 points across providers). One of the worst places in finance to deploy AI without domain expertise. Skip. |
| **Backtesting engine** | Requires a 10-year clean dataset we don't have and won't get free. Out of scope. |
| **Options pricing / Greeks** | Black-Scholes is fine and trivially scriptable; full vol surface requires paid data. Skip. |
| **Mobile-first UI** | Analysts work on laptops; retail phone users aren't the v1 audience. Pick an audience per release. |
| **Open chat over the memo** | Sounds great, UX disaster. Every follow-up burns context; every answer invents detail without memory. Build as flow-with-retrieval instead. |
| **More analyst agents (per-sector / per-asset)** | Forbidden by pluggable policy. Anthropic and LangChain research: low-variance extra agents amplify blind spots. Sectors are knowledge packs, not agents. |

## The litmus test for any new feature

Every new feature must pass **all three** questions below. If it fails any, cut.

1. **Which of the 5 jobs above does this move?** If "all 5 weakly" — cut.
2. **Is this measurable?** If the answer is "we'll know if users complain" — cut. Define the metric before shipping.
3. **Does the runtime actually produce it?** If the runtime doesn't exist yet, the feature is a hope, not a feature. Build the runtime first; the feature second.

## Where the user jobs become product decisions

- **Trust** → Memos must always carry a citation. The thesis register (P0 item 6) preserves provenance.
- **Action** → Memos must have a bottom line. Devil's-advocate must run. Next-catalyst must surface.
- **Speed** → Free models + cached tools + parallel agent calls + 5-prompt boundary.
- **Defensibility** → Forensic + citation + bear case in the same flow as the bull.
- **Comparison** → Flow f2, with cross-name normalization.

---

## Where this list might be wrong

Three assumptions are worth pressure-testing as the project ships:

1. **Wharton teams are the v1 audience.** If real adoption is retail, the "comparison is job 5" rank might be too low.
2. **5 user jobs is the right granularity.** If a user is doing something we don't have a job for (e.g. we're their whole brief, not just a first-pass draft), the rank shifts.
3. **No-build items stay no-build.** Real-time prices may become important if a user pays for them. Trading may return if the project becomes a brokerage-adjacent tool. **Each is a one-line revision to this file** when the underlying assumption is falsified by shipped behavior.

The list is a hypothesis. The evals and shipping behavior are what falsify it.
